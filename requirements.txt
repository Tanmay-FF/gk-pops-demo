# PINNED ON PURPOSE — these three decide what the tracker actually does.
#
# ultralytics, numpy and opencv-python were unpinned (ultralytics was not
# listed at all), so every install resolved whatever was newest that day. That
# is how the conda `all` env and venv_gk-pops-enhanced drifted onto ultralytics
# 8.4.19 vs 8.4.40 and produced materially different POPS output from the same
# video — see engine/ultralytics_compat.py for what changed between them.
#
# The compat shim makes those two versions agree again, and
# tests/test_bytetrack_low_confidence_recovery.py fails loudly if a future
# version breaks the same guarantee. Pinning is the other half: it stops the
# drift happening silently in the first place. Raise a pin deliberately, then
# re-run tests/ before committing the bump.
#
# torch/torchvision are NOT pinned here on purpose: the CUDA builds come from
# https://download.pytorch.org/whl/cu128, which needs an --index-url that a
# plain `pip install -r requirements.txt` does not pass. Those pins live in
# create_virtual_env.py, which installs them before this file.
#
# Note this file is a generated kitchen-sink dump and is NOT installable as-is
# anyway — it carries pre-existing lines like `torchaudio==2.6.0+cu124` and
# `torch_tpu==0.0.0` that plain PyPI cannot resolve. create_virtual_env.py is
# the supported path. The three pins above are the ones that matter for output
# reproducibility; the rest of the file was not audited.
